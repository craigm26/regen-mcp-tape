Both fail on every attempt, on Linux and on Windows. Five earlier builds passed them. The builder
chose not to join the input thread so that `tape` cannot block on a client that keeps its input
open (REQ-FW-005), and in doing so dropped messages it had already forwarded. The spec states
both halves; no text change.

## What this run taught
The line-end sentence worked: this Python build's own tests passed on Windows, the first to do so.
The run failed elsewhere, on the one thing every earlier build had got right: when the server
exits first, the messages the client already sent must still reach the trace. It is the kind of
error the brief expected from protocol plumbing, a race between forwarding and logging at
shutdown, and the suite caught it. With six runs used, Python is not released.
